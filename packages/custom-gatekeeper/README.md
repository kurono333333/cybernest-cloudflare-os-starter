# Custom Gatekeeper

This is a deployment-owned, credential-free Manager Knowledge Base for Cloudflare OS. It exposes current sources through the native singleton, records reads as observations, and submits full-document updates to the native manual approval queue before Core adoption.

## Adapt it

Change only the pieces your integration needs:

- `src/types.d.ts`: the checked reference for the four Agent-facing Knowledge Base methods.
- `src/types-code.ts`: the runtime declaration returned to the Agent; keep it synchronized with `types.d.ts`.
- `src/custom.ts`: owns bounded current reads, native observations, staged proposals, and approval callbacks.
- `src/custom.ts`: update only deployment-owned vendor, account, resource, and binding metadata when the integration changes.
- `wrangler.jsonc`: add non-secret bindings/variables and a migration when adding Durable Object classes.
- `deployment.jsonc`: provide deployment values and keep the `GATEKEEPER_CUSTOM` service binding generated by `scripts/deploy.mjs`.

Put API tokens and OAuth credentials in Wrangler secrets, never `wrangler.jsonc` or `deployment.jsonc`.

## Observation and approval policy

The Knowledge Base is private to its Manager. Read methods require native observation authorization, observer addition is rejected, and no action is auto-approved. `proposeUpdate()` stores the exact UTF-8 body and submits a bounded preview; Core is called only by `applyAction()` after native manual approval.

Use upstream's [`write-gatekeeper` skill](https://github.com/cloudflare/cloudflare-os/blob/main/.agents/skills/write-gatekeeper/SKILL.md) when changing the native Gatekeeper lifecycle, approval semantics, observer policy, or UI integration.
